# Git Next

> **무슨 일이 일어났는지 보세요. 실수하기 전에 멈추세요.**

Git은 어렵게 느껴질 수 있습니다.
GitLens 같은 강력한 도구가 있어도, 초보자는 여전히 “지금 눌러도 되나?”가 무섭습니다.

매일 Git을 사용하고 있어도, 지금 저장소 안에서 정확히 무슨 일이 일어나고 있는지 한눈에 이해하기 어려운 순간이 있습니다.
그건 경력이나 실력의 문제가 아닙니다.

Git Next의 목표는 기능 경쟁이 아닙니다.
**실수 방지와 두려움 완화**입니다.

커밋, 브랜치, 변경 사항, 로컬과 원격의 관계를 눈으로 확인하고,
위험한 작업 앞에서는 상태·위험·다음 행동을 먼저 보여 줍니다.

모든 명령어를 외울 필요도 없고,
실수를 지나치게 두려워할 필요도 없습니다.

Git의 많은 실수는 상태를 이해하면 되돌리거나 수습할 수 있습니다.

---

## 왜 Git Next인가요?

Git에서 가장 답답한 순간은 명령어를 모를 때보다 **현재 상태를 모를 때**입니다.

- 지금 내 브랜치는 원격보다 앞서 있나, 뒤처졌나?
- Pull 해도 괜찮은가?
- Push가 왜 거절됐나?
- 충돌이 났는데 어떤 변경이 내 것인가?
- 지금 되돌릴 수 있는가?
- Rebase나 Force Push가 정말 필요한가?

Git Next는 단순히 명령어 하나를 대신 실행하는 데 집중하지 않습니다.

```text
현재 상태 확인
      ↓
무슨 일이 일어났는지 설명
      ↓
주의할 점 확인
      ↓
다음 행동 선택
      ↓
필요하면 안전하게 실행
```

먼저 이해하고, 그다음 움직일 수 있게 만드는 것이 목표입니다.

---

## 🌿 Git을 눈으로 이해하기

커밋, 브랜치, HEAD, 로컬/원격 ref를 그래프에서 한눈에 확인할 수 있습니다.

분기와 병합 흐름을 따라가며 **지금 내가 Git의 어디에 서 있는지** 빠르게 파악할 수 있습니다.

검색, 범위 필터, 최근 커밋 제한, Compact Mode도 지원합니다.

---

## 🛡️ Safe Guard

위험한 Git 작업 앞에서 “지금 상태가 뭔지 / 왜 위험한지 / 다음에 뭘 하면 되는지”를 먼저 보여 줍니다.

Safe Guard가 직접 막는 대표 규칙:

- 더러운 작업 폴더와 들어오는 변경이 겹칠 때
- 원격 브랜치 연결(upstream)이 없을 때
- 원격 이력이 다시 쓰인 흔적이 있을 때
- `main` / `master` / `release/*` 같은 보호 브랜치에서 위험한 이력 변경을 시도할 때

그 밖의 Pull/Push 미리보기, 충돌·진행 중 작업 복구, 브랜치 전환 안내는 Safe Guard와 상황 가이드가 함께 도와줍니다.

Safe Guard는 단순히 `실패`나 `위험`이라고 끝내지 않습니다.

- 현재 저장소 상태
- 왜 주의가 필요한지
- 어떤 문제가 발생할 수 있는지
- 다음에 무엇을 할 수 있는지

> Git Next는 Force Push나 기록 삭제를 쉬운 해결책처럼 먼저 권하지 않습니다.

---

## 🔧 필요한 Git 작업을 한곳에서

Git Next에서는 그래프를 보면서 주요 Git 작업으로 자연스럽게 이어갈 수 있습니다.

- Pull / Push와 ahead / behind / diverged 상태 확인
- 브랜치 생성, 전환, 비교, Merge, 이름 변경, 삭제
- Tag와 Stash 관리
- Stage / Unstage / Commit
- Cherry-pick / Revert
- Remote 관리
- Undo / Reflog
- Merge / Rebase / Cherry-pick / Revert 진행 중 상태 확인과 복구
- Conflict 상황 안내

Git 고유 용어를 감추지는 않습니다.
대신 처음 보거나 오랜만에 보는 용어라도 흐름을 따라갈 수 있도록 설명을 함께 제공합니다.

---

## 🚑 실수해도 다시 이해할 수 있게

실수했다고 바로 터미널부터 열 필요는 없습니다.

Git Next는 현재 상태와 복구 의미를 먼저 보여주고,
가능한 경우 다음 행동으로 이어질 수 있게 도와줍니다.

Undo, Reflog, Conflict 복구와 함께
Merge, Rebase, Cherry-pick, Revert가 진행 중인 상황도 확인할 수 있습니다.

중요한 것은 **실수를 하지 않는 것**보다,
**무슨 일이 일어났는지 이해하고 다시 선택할 수 있는 것**이라고 생각합니다.

---

## 🧭 Git Next가 지키는 원칙

1. 위험한 작업은 실행 전에 설명합니다.
2. 모르는 상태를 안전하다고 단정하지 않습니다.
3. Git 원문은 보존하되 이해하기 쉬운 설명을 함께 제공합니다.
4. Force Push와 기록 삭제를 지름길처럼 권하지 않습니다.
5. 마지막 판단은 사용자에게 남겨둡니다.

---

## 🌐 다국어 지원 (Localization)

Git Next는 한국어와 영어를 지원합니다.

- **기본 언어**: 한국어 (`ko`)
- **지원 언어**: 한국어 (`ko`), 영어 (`en`)
- **언어 감지**: VS Code 환경 설정(`vscode.env.language` 또는 `VSCODE_NLS_CONFIG`)에 따라 언어를 자동으로 감지합니다.
- **Fallback 동작**: 지원하지 않는 로케일이거나 번역 키가 누락된 경우 기본 언어인 한국어(`ko`)로 자동 대체(fallback)되며, 번역 키가 어디에도 없는 경우 키 식별자를 안전하게 반환합니다.

## 🤖 AI 진단 (선택)

설정에서 AI Provider를 켜면, 지금 저장소 상황을 기존 가이드 카드 형식으로 진단할 수 있습니다.

- 기본값: 꺼짐 (`gitNext.ai.provider = off`)
- 선택: Codex / Ollama 로컬
- AI는 임의 HTML을 만들지 않고, 허용된 가이드 스키마와 액션만 사용합니다.

## Roadmap

Git Next는 아직 1.0을 향해 발전하고 있습니다.

앞으로의 우선순위는 기능 확장보다 **공포 순간을 끝까지 데려다 주는 완성도**입니다.

- 충돌·진행 중 작업 복구 흐름 다듬기
- 첫 저장소 / 첫 Commit 성공 경로 강화
- Safe Guard 안내와 실제 보호 범위의 일관성 유지

기능을 많이 추가하는 것보다,
Git을 더 잘 이해하고 더 안전하게 사용할 수 있게 만드는 방향을 우선합니다.
