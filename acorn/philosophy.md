# Acorn Philosophy

- Token efficiency is the default. Do not read, plan, generate, or do work that does not materially help the current task.
- YAGNI: build only what the current request requires. Do not add speculative features, abstractions, configuration, automation, or future work.
- Keep small work small. Add process only when it earns its cost.
- Use the minimum context needed to make the next correct move.
- Delta first: if the receiver already has valid context, pass only changed facts, decisions, dependencies, blockers, and the next action.
- Acorn provides defaults and capabilities, not mandatory team structure. Projects may choose executors, transport, QA, and role assignments that fit their work while preserving the lifecycle contracts they rely on.
- Human focuses on real decisions; Coordinator handles routine planning, routing, and review by default.
- Automation is opt-in. Human can pause, override, redirect, or resume at any workflow boundary.
- Start planning lightweight. Do not force deep planning for obvious or trivial work.
- Ask whether to plan deeply only when major/ambiguous work requires a costly-to-reverse direction choice. Do not ask for minor work or when direction is already clear.
- If deeper planning is useful and the Human agrees, use an available configured planning skill such as Superpowers.
- When the direction is already clear, proceed without ceremony.
- Implementation stays lean with Ponytail; communication stays lean with Caveman.
- Verification is evidence, not ritual. Run the smallest useful checks and never invent PASS.
- Work dirty, close clean: keep active work lightweight, then reconcile project truth at closeout.
