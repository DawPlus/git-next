# Recognize linked Git worktrees

## Goal

Warn and summarize when the repository has other worktrees so users do not operate in the wrong tree by accident.

## Do

- Detect sibling worktrees for the current repository.
- Show a compact summary of path and checked-out branch when available.
- Warn before risky actions if another worktree may be affected or if the user appears to be in an unexpected tree.

## Keep

- Read-only discovery by default; do not create/remove worktrees in this ticket.
- Keep warnings conservative and actionable.
- Avoid noisy banners when only one worktree exists.

## Done

- Multi-worktree repos surface a clear summary in Git Next.
- Risky actions can mention worktree context when relevant.
- Focused tests and build pass.

## Result

Added linked-worktree discovery with current path/branch status, quiet single-worktree behavior, visible sibling summaries, and sibling context in mutation confirmations. Verified 33 focused tests, build, and diff check.
