# Add AI diagnosis provider and guide-card schema

## Goal

Let Git Next send the current Git situation to a configurable AI provider and render the diagnosis inside the existing guide-card/animation system instead of inventing a separate AI UI.

## Do

- Define a small provider boundary for AI diagnosis. Initial adapters may target local AI CLIs such as Codex/Claude/Gemini-style commands, local LLMs such as Ollama, or another configurable provider.
- Send only the Git context needed to diagnose the current situation: branch/upstream state, ahead/behind/diverged, dirty/conflict state, in-progress operation, recent failed action, and relevant Safe Guard findings.
- Require a validated structured response: situation, summary, risk, next action, guide/preset key, recommended Git Next action, and confidence.
- Reuse existing situation-guide cards, animation presets, Korean terminology, and existing Git Next actions whenever the AI maps to a known situation.
- Provide one generic fallback card/preset for valid diagnoses that do not match a built-in guide.
- Expose two user paths from an AI diagnosis: understand/learn the situation, or ask Git Next to resolve it.
- The resolve path must route through existing Git Next Safe Guard, preview, confirmation, and action flows rather than letting the AI execute arbitrary Git commands directly.
- If no provider is configured, guide setup instead of failing silently.

## Keep

- Provider-neutral core. Do not hard-code the product to one AI vendor.
- AI diagnoses and recommends; Git Next owns UI, mutation, safety, and confirmation.
- AI must not return executable HTML/CSS/JS or arbitrary shell commands.
- Reuse existing guide cards and animation assets first.
- Keep prompts/context small and Git-focused.
- Do not commit.

## Done

- A configured provider can diagnose the current Git state using the shared schema.
- Known situations render with existing guide-card design and animation presets.
- Unknown-but-valid diagnoses render with the generic AI diagnosis card.
- Recommended actions connect to existing Git Next safe flows.
- Invalid provider output is rejected safely with a useful error.
- Focused tests and build pass.
