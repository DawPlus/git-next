# T-261006-01 — Introduce i18n foundation

## Goal
Create a small localization foundation that can serve all Git Next UI without changing existing behavior.

## Do
- Add a shared i18n module with `ko` and `en` locales.
- Provide `t(key, params?)` with parameter interpolation and deterministic fallback behavior.
- Detect the current VS Code UI language and normalize it to a supported locale.
- Keep Korean as the current product default/fallback unless an explicitly supported locale is selected.
- Define key naming and namespace conventions so later tickets can migrate strings without one giant locale file.
- Add focused tests for locale selection, fallback, missing keys, and interpolation.

## Keep
- Do not migrate large UI surfaces in this ticket.
- Do not change Git behavior, Safe Guard behavior, or existing action flow.
- Keep the API usable from both `.ts` and `.mts` source modules.

## Done
- Shared i18n API exists and is covered by tests.
- `ko` and `en` dictionaries can resolve the same sample keys.
- Unsupported locales fall back predictably.
- Typecheck and focused tests pass.

## Result
- Added shared `ko`/`en` translation API, locale normalization, fallback, interpolation, and TS/MTS compatibility.
- Coordinator review and QA passed: `npm run typecheck`; `npx tsx --test test/i18n.test.mjs` (10 passed).
- Limitation: UI string migration is intentionally assigned to follow-up tickets.
