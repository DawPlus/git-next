# T-261007-06 — Add lightweight performance tracing for Git Next

## Goal
Make responsiveness problems measurable by recording timing for key Git, state-loading, sync, and render paths in development/debug mode without affecting normal users.

## Do
- Add lightweight timing helpers for important performance boundaries.
- Measure at least:
  - individual Git subprocess duration
  - `getState()` total duration
  - major `getState()` sub-reads where practical
  - `renderPanel()` duration
  - Help live-context loading duration
  - Push/Pull preflight duration
  - Push/Pull impact-preview preparation duration
  - actual network Git operation duration
  - post-action state refresh duration
- Include a short operation label and repository identity/path-safe identifier in trace output.
- Keep tracing disabled by default for normal users.
- Enable tracing only through a development/debug mechanism such as an environment flag, extension development mode, or explicit debug setting.
- Prefer structured, compact log lines so slow spans are easy to compare.
- Allow slow-operation highlighting using a simple threshold, without adding a heavy telemetry or analytics dependency.
- Avoid logging file contents, commit messages, credentials, remote URLs with secrets, or other sensitive repository data.
- Keep tracing overhead negligible when disabled.

## Keep
- Do not send performance data to any external service.
- Do not add product analytics or user tracking.
- Do not change Git behavior, Safe Guard decisions, UI behavior, or execution ordering; tracing must be observational only.
- Do not make production responsiveness worse just to collect timing data.
- Preserve existing logging/output behavior unless debug tracing is explicitly enabled.

## Done
- Developers can enable performance tracing and see timing for core Git Next interaction paths.
- Slow Help, refresh, Push, and Pull flows can be broken down into measurable spans.
- Disabled tracing adds effectively no meaningful runtime overhead.
- Trace output avoids sensitive repository data.
- Focused tests cover trace enable/disable behavior and safe output formatting.
- Full tests, typecheck, and build pass.

## Result
- Added opt-in performance tracing via `GIT_NEXT_PERF=1`; normal users remain untraced by default.
- Added path-safe hashed repository identifiers and sanitized operation labels; raw repository paths, remote URLs, credentials, file contents, and commit messages are not logged.
- Added timing around Git subprocess wrappers, `getState()` and its major sub-reads, `renderPanel()`, Help live-context loading, Push/Pull preflight, impact preview preparation, network progress spans, and before/after state snapshots.
- Added focused tests for opt-in enablement, disabled no-log behavior, enabled logging, slow-span marking, and path-safe output.
