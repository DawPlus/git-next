# T-261007-02 — Make Push/Pull actions respond immediately

## Goal
Improve perceived and actual responsiveness of Push/Pull by removing artificial preview delays and giving users immediate feedback that their click was accepted.

## Do
- Remove per-commit `setTimeout` delays from the Push/Pull movement preview.
- Keep the movement preview informative, but render it without serial animation delays.
- If any transition delay remains, keep the total delay minimal and independent of commit count.
- When Push or Pull is clicked, immediately mark the action as pending in the webview.
- Disable the triggering Push/Pull control while that action is in progress.
- Show a clear pending label/state such as `Push 중...` or `Pull 중...`.
- Prevent overlapping Push/Pull requests for the same repository while one sync action is already running; a second click must not start another Git network mutation.
- Always clear the pending state on success, failure, cancellation, or thrown error.
- Keep current confirmation, impact preview content, Safe Guard decisions, and network progress behavior; only remove presentation-only waiting that does not affect the decision or Git result.

## Keep
- Preserve existing Pull/Push confirmation flow.
- Preserve Safe Guard checks and blocked/warning behavior.
- Preserve network-operation progress notifications.
- Do not allow duplicate network Git operations for the same user action.
- Do not change Git semantics or safety behavior.

## Done
- Push/Pull no longer wait 220 ms per displayed commit or 400 ms for an empty preview.
- Clicking Push/Pull produces visible feedback immediately.
- Repeated clicks while the action is pending do not start duplicate operations.
- Pending UI clears reliably for success, blocked, cancelled, and failed flows.
- Focused tests cover duplicate-click prevention and pending-state cleanup.
- Full tests, typecheck, and build pass.

## Role
worker

## Result
- Removed the 400 ms empty-preview delay and both 220 ms per-commit Push/Pull preview delays while preserving the existing preview content and confirmation flow.
- Added immediate webview pending state for sidebar and graph Push/Pull controls; both sync controls are disabled during the active request and the triggering label changes to `Push 중...` or `Pull 중...`.
- Pending state survives patch-style webview refreshes through the existing `gitnext:refresh` event and restores the original button labels after completion.
- Added a repository-scoped extension-host sync lock so overlapping Push/Pull requests cannot start a second network mutation for the same repository.
- Pending/lock cleanup is handled in `finally`, including success, blocked/cancelled flows, and thrown errors. Duplicate requests from another view are rejected and that view's temporary pending state is cleared.
- Added focused source tests covering delay removal, immediate pending UI, repository lock, and cleanup paths.
