# Diagnose sporadic slow Git refresh and skip redundant redraw

## Goal
Reduce unnecessary Git state refresh/UI redraw after Stage without hiding external Git changes.

## Evidence
- Real reports: internal Stage takes ~94-125ms, but subsequent full state refresh ~764-5780ms.
- Multiple unrelated commands (log, for-each-ref, worktree, config) occasionally consume ~5100ms; source Git child-process wrapper has no 5000ms timeout/retry configured.
- Existing internal event guard validates recent Stage against real working tree and VS Code HEAD, falling back to full refresh on differences.

## Changed
- When all affected roots are verified unchanged internal Stage echoes, skip redundant UI redraw rather than always replacing the DOM.
- Preserve normal full refresh + render for any real external change or uncertain result.

## Follow-up: repeated Stage/Unstage burst
- User observed a single Stage total 102ms but subsequent full refreshes 5931ms and 931ms; repeated clicks feel progressively sluggish.
- Cause in scheduler: debounce prevented queued timers from duplicating, but a running refresh did not prevent another concurrent refresh.
- Added single-flight external Git refresh processing. Events arriving during an active pass remain queued and are rechecked in one trailing pass. External change fallback remains intact.
- New focused regression test 3/3 passed, typecheck and build passed. Full suite invocation was blocked by tool safety policy; no full-suite pass claim. Manual burst QA still pending.
