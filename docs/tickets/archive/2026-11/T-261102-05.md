# T-261102-05 — Cut Push/Pull preflight latency after perf bench

## Goal
Reduce Push/Pull click delay caused by host-side preflight (~175-200ms median on M4), without weakening Safe Guard.

## Do
- Profile `preflightPushSafety` / `preflightPullSafety`: `detectRemoteHistoryRewrite` (~95-100ms) dominates via fetch + many rev-parse.
- Reuse recent remote-freshness / snapshot within one sync click; avoid duplicate fetch when impact preview already refreshed.
- Keep fail-closed when remote state is unknown.
- Re-run `npm run perf:bench` and record before/after medians for 10/100/500.

## Keep
- No force-push shortcuts; no silent skip of rewrite detection on real sync.
- Mistake-prevention goal stays above raw speed.

## Done
- Push/Pull preflight median drops meaningfully on `perf:bench` without safety regressions.
- Tests + typecheck + build pass.

## Role
worker

## Read
- src/git-preflight.mts
- scripts/perf-bench.mjs

## Result
- `getInProgressOperation`: one `--git-dir` + FS marker checks (was up to 5 sequential `rev-parse --git-path`).
- `detectRemoteHistoryRewrite`: parallel before/upstream reads; single-flight for concurrent callers; freshness mark no longer blocks return. Sequential calls still fetch (fail-closed for new remote commits between clicks).
- Push/Pull preflight: parallel local checks; Pull parallelizes tracking + incoming after fetch.
- `inspectCurrentUpstreamLocal`: parallel config/remote checks.
- Bench before ~175-200ms → after medians push ~75-78ms / pull ~86-87ms (files 10/100/500).
- Verified: `npm test` 309 pass, typecheck, build, `perf:bench`; new `test/rewrite-detect-cache.test.mjs`.
