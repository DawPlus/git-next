# T-261005-38 — Simplify beginner-facing Git messages

## Goal
Make normal Git Next actions understandable without requiring users to know internal Git terms such as HEAD, upstream, ref, diverged, detached HEAD, or force-with-lease.

## Do
- Audit user-facing copy in normal action flows: confirmations, warnings, errors, Safe Guard hints, Git Doctor recommendations, Branch/Remote/Tag actions, Pull/Push, and recovery prompts.
- Rewrite primary messages around two questions:
  - what is happening now
  - what the user should do next
- Replace implementation jargon in normal flows with plain descriptions, for example:
  - HEAD -> current branch/current commit
  - upstream -> connected remote branch
  - ref -> branch/tag/remote target as appropriate
  - diverged -> local and remote both have different new commits
  - detached HEAD -> currently viewing a commit without being on a branch
  - force-with-lease -> only keep the technical name when the risky action itself must be identified, paired with a plain-language explanation
- Keep exact technical terms in glossary/learning/detail surfaces where teaching the term is the purpose.
- Keep raw Git command/output details available only in detail/debug contexts.
- Add focused regression tests for representative beginner-facing messages.

## Keep
- Do not change Git behavior, safety decisions, or action availability.
- Do not hide risk for destructive actions.
- Do not remove technical terms from the terminology/learning center.
- Prefer concise Korean copy over long explanations in primary UI.
