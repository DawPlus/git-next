# T-261008-02 — Add CI quality gate for pull requests

## Goal
Make repository quality visible and repeatable by running the same release checks automatically on every push and pull request.

## Do
- Add a GitHub Actions workflow for supported Node versions.
- Run dependency install with the lockfile.
- Run `npm test`, `npm run typecheck`, and `npm run build`.
- Cache package-manager dependencies where useful without hiding lockfile drift.
- Fail clearly when tests, typecheck, or build fail.
- Keep the workflow small and easy to inspect.

## Keep
- Do not add deployment or marketplace publishing automation in this ticket.
- Do not introduce unrelated linting/tooling dependencies.
- Keep local scripts as the source of truth.

## Done
- Push/PR CI automatically runs tests, typecheck, and build.
- CI fails on any failed quality gate.
- README or contributor docs mention the CI gate only if useful.
- Workflow is verified on GitHub or validated locally as far as practical.

## Role
worker

## Read
- `package.json`
- `.github/workflows/`
