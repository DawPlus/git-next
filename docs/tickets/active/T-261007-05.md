# T-261007-05 — Share repository state across simultaneous webview refreshes

## Goal
Reduce duplicate Git state reads when multiple Git Next webviews refresh at nearly the same time by sharing one repository-state load per refresh cycle.

## Do
- Deduplicate concurrent `getState()` calls for the same repository.
- Reuse the same in-flight Promise when sidebar, graph, and other webviews request state simultaneously.
- Allow one freshly loaded repository state to drive multiple webview renders in the same refresh cycle.
- Keep the sharing window short-lived and scoped to the active refresh burst; do not introduce a long-lived global repository cache.
- Preserve the existing external Git change debounce and combine repeated refresh events where possible.
- Before an internal mutating Git operation, invalidate any reusable completed state; after the mutation, ensure the next shared state load is fresh.
- If an older in-flight state load completes after invalidation, do not let it become the post-mutation shared state.
- Clear or invalidate any in-flight/shared refresh state when the repository root changes.
- Keep fallback behavior simple: if shared state loading fails, each consumer should receive the same failure and the next refresh may retry normally.

## Keep
- Preserve existing sidebar and graph rendering behavior, including current refresh triggers and user-visible state.
- This ticket may deduplicate computation but must not suppress a refresh event that previously produced a meaningful visible update.
- Preserve immediate post-mutation freshness.
- Do not reuse stale state across unrelated user actions.
- Do not weaken remote freshness rules introduced by T-261007-01.
- Keep multi-repository and multi-root workspace behavior correct.

## Done
- Simultaneous sidebar/graph refreshes for one repository trigger one repository-state load instead of duplicate loads.
- Repeated external Git events within the debounce window do not cause redundant state reads.
- A successful mutation invalidates shared refresh state before the next render.
- Different repositories do not share state with each other.
- Failed shared loads are not permanently cached.
- Focused tests cover concurrent deduplication, post-mutation invalidation, failure retry, and multi-repository separation.
- Full tests, typecheck, and build pass.

- Added generation-based invalidation so state loads started before a mutation cannot become the shared post-mutation load.
- Internal Git mutations invalidate shared state both before and after execution.
- Repository-root changes clear shared state.
- Failed state loads are removed in `finally`, allowing later refreshes to retry normally.
- Separate repository keys keep concurrent state loads isolated.
- Existing external Git refresh debounce remains unchanged.
