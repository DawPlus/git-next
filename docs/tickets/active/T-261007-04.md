# T-261007-04 — Load repository context lazily in Help panels

## Goal
Make Help, glossary, and guide panels open immediately while preserving live repository-aware guidance such as “현재 저장소는 이런 상황입니다.”

## Do
- Open the Help/Knowledge panel immediately with static explanatory content.
- Do not block panel creation on a full `getState()` call.
- Load live repository context asynchronously after the panel is visible.
- Update only the repository-aware section when live context becomes available, without changing the wording, classification, or meaning of the existing live guidance.
- Introduce a lightweight Help-specific repository context if the panel needs only a subset such as:
  - current branch
  - tracking/ahead/behind
  - working-tree changes
  - in-progress Git operation
- Avoid loading commit history, full refs, linked worktrees, or remote freshness unless a specific Help surface truly needs them.
- Reuse already-available/cached repository state when safe instead of spawning new Git subprocesses solely because Help was opened.
- Show a small non-blocking loading state such as “현재 저장소 상태 확인 중...” for the live-context section.
- If repository context loading fails or the remote is unavailable, keep the Help content usable and show the live-context section as unavailable/unknown rather than blocking the panel.

## Keep
- Preserve repository-aware Help behavior and beginner guidance.
- Preserve the current ability to compare glossary/guide concepts with the user’s actual repository state.
- Preserve the same repository-aware classifications and examples; this ticket changes when the context loads, not what the context means.
- Do not remove live state simply for speed.
- Do not weaken Safe Guard or sync behavior.
- Keep normal Help content available even outside a Git repository.

## Done
- Help/Knowledge panel becomes visible before repository context loading completes.
- Static Help content does not wait for `getState()`.
- Repository-aware sections update after lightweight context resolves.
- Opening Help does not trigger unnecessary commit-history, full-ref, worktree, or remote-freshness reads.
- Failure to load live repository context does not prevent Help from opening.
- Focused tests cover immediate render, async context update, and failure fallback.
- Full tests, typecheck, and build pass.
