# T-261005-39 — Redesign Branch workspace around Local ↔ Remote relationship

## Goal
Make the Branch workspace understandable to Git beginners by showing Local and Remote as two clear areas, visualizing their connection, and keeping normal branch creation Local-first.

## Do
- Redesign the Branch workspace into two side-by-side areas:
  - left: Local
  - right: Remote
- Keep connected Local/Remote branches visually linked with the existing connection-line concept.
- Let users select a Local branch and clearly see which Remote branch it is connected to.
- Keep branch creation only on the Local side with a clear `+` action.
- When creating a Local branch, explain:
  - "현재 로컬에 새로운 브랜치를 생성합니다."
  - "원격에는 생성되지 않아요. Push하면 원격에도 생성됩니다."
- Do not show a Remote `+` button. Remote branches are created as the result of Push.
- Present the Remote side as a protected area with a subtle yellow/warning treatment and shield icon.
- Show beginner-facing guidance in the Remote area:
  - "여기는 로컬에서 직접 수정하지 않아요."
  - "Local에서 작업한 뒤 Push하면 원격에 반영됩니다."
- Support dragging a Remote branch into the Local area to create a connected Local branch.
- On Remote → Local drop:
  - suggest a Local branch name from the Remote branch name
  - allow the user to edit the name
  - create the Local branch
  - connect it to the selected Remote branch
  - make the resulting connection visible immediately
- Keep the main Branch workspace actions minimal:
  - 새 로컬 브랜치
  - 동기화
  - 원격 새로고침
- Move secondary operations such as compare, switch, rename, delete, merge, and cleanup out of the always-visible primary toolbar and expose them contextually when a branch is selected.
- Make the sync action reflect the selected/current Local ↔ Remote relationship and work with Safe Guard guidance.
- "원격 새로고침" should update Remote branch information without changing working files, and its helper text should make that clear.

## Keep
- Preserve existing Safe Guard checks and destructive-action confirmations.
- Do not change underlying Git safety behavior.
- Remote branches remain inspectable/selectable even though direct create/edit controls are removed from the primary UI.
- Keep technical Git terms available in details/learning surfaces, but keep the primary Branch workspace beginner-friendly.
- Preserve the existing visual connection concept where useful rather than adding a second relationship model.

## Done
- Local and Remote are visually distinct at a glance.
- Connected branch pairs are visibly linked.
- New Local branch creation clearly explains that Remote is unaffected until Push.
- Remote has no direct create button.
- Remote is visually presented as a protected area with clear beginner guidance.
- Dragging Remote → Local creates a named Local tracking branch and shows the connection.
- Main toolbar contains only the minimal branch actions.
- Secondary branch actions remain accessible contextually.
- Sync and Remote refresh behavior remain safe and understandable.
- Focused Branch workspace tests pass.
- Full tests and build pass.
