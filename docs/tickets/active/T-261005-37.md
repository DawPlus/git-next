# Make Safe Guard guidance action-first and beginner-friendly

## Goal

Make Safe Guard immediately tell Git beginners what they should do next, so they do not have to interpret raw Git state such as ahead, behind, dirty, or diverged.

## Do

- Treat Safe Guard as the primary next-action guide, not just a status badge.
- Prefer direct action wording over Git-state jargon.
- Cover the main beginner flows with explicit messages:
  - local changes before Commit
  - remote ahead before Commit/Push
  - Commit completed but not yet Pushed
  - local and remote fully synchronized
  - no upstream / first Push
  - diverged history
  - merge/rebase/cherry-pick/revert in progress
  - unknown or unavailable remote state
- Make the message answer two questions at a glance:
  - "지금 상태가 뭐야?"
  - "그래서 지금 뭘 해야 해?"
- Examples:
  - "Commit 전에 Pull을 먼저 진행해주세요."
  - "Commit 완료! 아직 Push하지 않은 Commit이 1개 있어요. Push해도 됩니다."
  - "로컬과 원격이 최신 상태예요."
  - "로컬과 원격이 갈라졌어요. Push 전에 Merge 또는 Rebase가 필요해요."
- Keep counts/details secondary. The first sentence should remain understandable without knowing Git terminology.
- Align wording with actual Safe Guard rules so the guide never recommends an unsafe next action.

## Keep

- Existing Safe Guard decision logic and protections.
- Existing icon/status color treatment.
- Existing details view for deeper Git information.
- Existing Pull/Push/Commit execution flows.
