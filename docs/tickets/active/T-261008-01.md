# T-261008-01 — Harden webview CSP nonce handling

## Goal
Make Content Security Policy a real last line of defense by removing automatic nonce injection from arbitrary `<script>` tags and ensuring only Git Next-authored scripts receive a valid nonce.

## Do
- Stop using regex-based post-processing that adds a nonce to every nonce-less `<script>` tag.
- Generate the nonce before rendering and pass it explicitly to view renderers that emit executable scripts.
- Add nonce only to known Git Next script tags at render time.
- Keep user/repository-derived content escaped before interpolation into HTML.
- Add security-focused regression tests proving an injected `<script>` string from branch names, commit messages, paths, or notices does not receive a valid nonce.
- Verify CSP remains compatible with current sidebar, graph, workspace, and patchable webview flows.

## Keep
- Preserve current CSP restrictions and `enableScripts` behavior.
- Do not loosen `script-src`, `style-src`, or other CSP directives to simplify implementation.
- Preserve existing webview functionality and localization.

## Done
- Arbitrary injected `<script>` markup cannot gain the active nonce.
- All legitimate Git Next webview scripts still execute normally.
- Focused XSS/CSP regression tests pass.
- Full tests, typecheck, and build pass.
