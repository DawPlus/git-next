# T-261008-07 — Split oversized panel handlers by responsibility

## Goal
Reduce maintenance risk in large handler modules by separating panel responsibilities without changing user-visible behavior.

## Do
- Identify coherent responsibilities currently concentrated in `panel-handlers.ts`.
- Extract small modules by workspace/panel domain rather than generic utility layers.
- Keep shared state and mutation boundaries explicit.
- Avoid circular dependencies.
- Preserve existing public exports and call flow where practical.
- Add or retain focused tests around extracted behavior.

## Keep
- No framework migration.
- No speculative abstraction layer.
- Do not split files only to reduce line count; each extraction must have a clear responsibility.

## Done
- `panel-handlers.ts` is materially smaller and easier to navigate.
- Extracted modules have clear ownership and minimal shared mutable state.
- No user-visible regressions.
- Full tests, typecheck, and build pass.

worker
