# Resolve diverged history with Merge or Rebase

## Goal

When local and remote have diverged, let beginners finish sync inside Git Next instead of stopping at explanation after `--ff-only` Pull fails.

## Do

- Detect diverged ahead/behind after Push rejection or failed ff-only Pull.
- Offer "Merge로 합치기" and "Rebase로 정리하기" with a result preview (commits in, expected tip, conflict risk when known).
- Require explicit confirmation before mutating.
- On conflicts, route to the existing in-progress merge/rebase continue/abort path.
- Refresh sidebar and graph after success or abort.

## Keep

- Keep default Pull as `--ff-only`; do not silently switch Pull to merge/rebase.
- Reuse existing Safe Guard, impact preview, and conflict-helper patterns.
- No force-push from this flow.

## Done

- Diverged state surfaces Merge and Rebase actions with preview and confirm.
- Successful Merge or Rebase leaves the branch syncable (or clearly blocked only by conflicts).
- Conflict path continues or aborts through existing helpers.
- Focused tests and build pass.
