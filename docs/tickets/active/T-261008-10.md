# T-261008-10 — Make failures lead directly to the next action

## Goal
Turn Git failures into actionable flows so users know what to do next instead of receiving an error and stopping.

## Do
- Audit common failure paths for Push, Pull, Commit, branch switching, stash, and in-progress operations.
- Map known failures to one clear next supported action where possible.
- Reuse retry checks, Git Doctor, conflict recovery, branch tools, and Safe Guard.
- Keep raw Git detail available for advanced users without making it the primary explanation.
- Avoid generic “try again” guidance when a specific recovery step is known.

## Keep
- Do not hide Git's original error detail.
- Do not auto-run destructive recovery actions.
- Preserve explicit confirmation for risky mutations.

## Done
- Common user-facing failures offer a concrete next action.
- Known Push/Pull and dirty/in-progress-operation failures no longer dead-end.
- Unknown failures still expose raw Git detail and a safe diagnostic path.
- Focused tests cover representative mapped and unmapped failures.

worker
