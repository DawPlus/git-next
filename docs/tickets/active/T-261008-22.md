# Open VS Code Merge Editor for conflicted files

## Goal
Help users resolve `<<<<<<< HEAD` / `=======` / `>>>>>>>` conflicts directly from Git Next without reimplementing the merge editor.

## Do
- Detect unmerged/conflicted files from Git status (including UU, AA, DD, AU, UA, DU, UD) and list them clearly in Git Next Source Control or Conflict Helper.
- Add an obvious "Merge Editor로 열기" action for supported conflicted files, using VS Code's built-in Merge Editor and a graceful fallback to normal editor / explanation if unavailable.
- Show conflict resolution progress. After the user edits and saves, refresh file status and offer Stage for resolved files.
- Keep Merge/Rebase/Cherry-pick/Revert Continue and Abort available via existing Conflict Helper, with explicit confirmation for risky actions.
- Add tests for conflict detection, open-editor command, unavailable-editor fallback, and transition from conflicted to resolved/staged.

## Keep
- Do not build a custom 3-way diff/merge editor.
- Do not automatically accept a side, overwrite user edits, Stage files, or continue/abort Git operations.
- Do not confuse branch-to-branch Merge with resolving conflict markers.
- Respect existing Git state, safeguards, localization and VS Code compatibility.

## Done
- A user with conflicted files can find and open VS Code Merge Editor from Git Next, resolve/save, Stage, and proceed to Continue without guessing which menu to use.
- Ordinary file changes do not show conflict actions.
- Tests, typecheck, build, and manual VS Code QA pass.
