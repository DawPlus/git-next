# 개발 원칙

이 프로젝트의 구현·수정·리뷰 기준. Acorn의 공통 가이드를 구체화하며, 스타일 선택은 이 문서를 우선한다. 작업 권한·역할 경계·필수 검증을 생략하는 근거로 사용하지 않는다. 유효한 세션에서 한 번 읽고 변경·맥락 유실 때만 다시 읽는다.

## 요청 범위와 원문 보존

- 요청받은 동작만 구현한다. 제품의 문구·내용·디자인·기능을 임의로 기획하거나 수정하지 않는다.
- 화면 문구·버튼명·안내·오류 메시지·콘텐츠는 승인 없이 추가·삭제·변경하지 않는다. 오탈자 수정이나 더 자연스러운 표현으로 다듬는 것도 포함한다.
- 추가·변경이 필요하면 이유와 구체적인 변경안(문구는 전후 원문)을 먼저 제시하고 의견을 묻는다. 답변 전에는 해당 변경을 적용하지 않는다. 승인된 독립 작업은 계속할 수 있다.
- 이미 요청·승인된 범위는 재확인 없이 진행한다. 새로운 제품 선택, 의존성 추가, 범위 확대가 생길 때만 확인한다. 새 화면·상태에 필요한 문구가 제공되지 않았다면 임의로 만들어 넣지 않는다.
- 주변 코드 정리·디자인 개선·기능 보완을 끼워 넣지 않는다. 기존 사용자 변경을 보존한다.

## 단순함과 일관성

- 사람이 유지보수하기 쉬운, 읽는 순서와 구조가 예측되는 코드를 쓴다. 짧은 코드보다 명확한 이름·일관된 흐름을 우선한다.
- YAGNI: 요청하지 않은 기능·옵션·추상화·공통화를 미리 만들지 않는다. 기존 코드·표준 라이브러리·설치된 도구를 우선한다.
- 같은 역할은 같은 구조·이름을 사용한다. 새 패턴을 만들기 전에 주변 코드와 프로젝트 관례를 확인한다. 관례를 맞춘다는 이유로 무관한 파일을 다시 쓰지 않는다.
- React 파일은 import → 타입·상수 → 컴포넌트 순서를 기본으로 한다. 컴포넌트 안에서는 hooks·상태·query → 파생 값 → 이벤트 처리 → 화면 반환 순서로 읽히게 한다. hooks는 조건부 호출하거나 early return 뒤에 배치하지 않는다.
- API 접근·queries·types·화면·모달은 각 책임에 맞게 분리한다. 파일 길이만으로 쪼개거나 한 번 쓰는 작은 표현까지 별도 파일로 만들지 않는다.
- 화면 전용 요소는 해당 기능/route 근처에 둔다. 라우팅에서 제외되는 폴더명은 실제 라우터 규칙을 확인한다. `-components` 같은 예시를 모든 프로젝트에 강제하지 않는다.
- Backend도 요청 처리·업무 로직·데이터 접근 등 책임에 맞게 나누되, 필요 없는 계층은 만들지 않는다.
- 공통화는 실제 반복과 공통 책임이 확인된 뒤 한다. 옵션·분기가 계속 늘면 분리가 더 단순한지 먼저 판단한다.

## 주석과 조건문

- `// 모달 상태`, `// Alert 선언`, `// 조회 조건`처럼 구역·목적을 짧게 표시한다. 특이한 처리는 필요한 이유를 한 줄로 남긴다. 코드 위 장문 설명이나 코드 내용을 그대로 반복하는 주석은 피한다.
- 예외·중단 조건은 early return을 우선한다. 하나의 값에 따른 여러 분기는 switch, 단순한 값 선택은 삼항 연산자를 사용한다.
- 중첩 삼항은 쓰지 않는다. 더 읽기 쉬우면 if/else를 사용한다. if 개수 자체를 줄이려고 불명확한 표현으로 바꾸지 않는다.

## UI·날짜·검증

- Tailwind는 `text-sm` 같은 약속된 토큰을 우선한다. `text-[12px]` 같은 임의의 고정 px 값을 흩뿌리지 않는다. 반복되는 새 값은 이름 있는 테마 토큰으로 제안하고, 디자인 변경 승인을 받은 뒤 적용한다.
- 날짜 계산·파싱·포맷은 date-fns를 우선한다. Date 객체 자체는 사용할 수 있지만 직접 날짜 연산·문자열 조립은 피한다. 설치되지 않았다면 의존성 추가를 먼저 제안한다. 무관한 기존 날짜 코드를 일괄 교체하지 않는다.
- 로딩·빈 상태·실패 상태도 구현 범위에서 확인한다. 기존 승인된 표현을 재사용하고, 새 문구·UX 선택이 필요하면 먼저 묻는다. 에러를 빈 catch로 숨기지 않는다.
- 변경에 맞는 최소 검증과 필요한 회귀 검사를 수행한다. 실패·미검증은 그대로 보고한다.

## 다국어 (i18n) 및 릴리스 검증

- **지원 언어 및 기본 로케일**: 한국어(`ko`, 기본값)와 영어(`en`)를 지원한다. 미지원 언어 또는 번역 키 누락 시 한국어(`ko`)로 결정론적 Fallback(대체)되며, 모든 로케일에 키가 없으면 키 이름을 반환한다.
- **네임스페이스 구조**: 사전은 `src/locales/<locale>/<namespace>.mts`로 분리하여 관리하며, `index.mts`에서 통합한다. 키는 `namespace.section.key` 형태의 점(dot) 표기법을 사용한다.
- **파라미터 보간**: 번역 템플릿의 가변 값은 `{param}` 또는 `{{param}}` 형태의 명명 파라미터를 사용하며, 번역 조각을 임의로 이어붙이지 않는다.
- **릴리스 품질 게이트**: 배포 전 `test/localization.test.mjs`를 통해 한국어/영어 100% 키 패리티, 번역 누락/미사용 검사, UI 노출 영역의 하드코딩 방지 스캔, 한국어/영어 스모크 렌더링을 확인한다. 모든 검증은 macOS와 Windows에서 동일하게 동작해야 한다.

## 토큰 절약

- 티켓의 Read, code_map, 정확한 심볼·경로 검색으로 필요한 부분만 읽는다. 전체 파일·저장소·archive를 습관적으로 로딩하지 않는다.
- 유효한 맥락·소스 발췌·검증 결과를 재사용한다. 코드 변경·누락된 근거·실제 위험이 있을 때만 다시 읽거나 검사한다.
- 불필요한 Agent 호출·중복 설명·대화 로그 복사를 피한다. 결과와 검증 근거를 짧게 남긴다. 토큰 절약을 이유로 필수 검증이나 승인 확인을 생략하지 않는다.
